Reference implementation

Which transformer does the record concern? The executable reference implementation runs the equipment-history reconciliation workflow on five synthetic scenarios, keeps the evidence behind each decision inspectable, and reproduces a transparent comparison with a simple baseline.

Executable Reference Release 0.2.2·Python 3.10 or later·Apache License 2.0

Source on GitHub Full comparison Generated walkthrough

What it implements

  • Explicit equipment identity corroborated by event-time installation history.
  • Preserved source evidence, conflicts, decision revisions and review records.
  • Review for missing identifiers and conflicting candidates; unresolved outcomes where evidence is insufficient.
  • Two documented input layouts mapped into the same processing engine.
  • A simple baseline, evaluation against separately held synthetic truth labels, and reproducible result reports.

The software implements deterministic association and review. It does not provide similarity scoring, machine learning, derived equipment-condition statuses, sensor analytics, cloud integrations, live reviewer authentication, a production data platform or operational control. Both automatic methods receive identical source evidence with review events removed. The baseline uses an explicit equipment identifier, or a unique current installation at receipt time when that identifier is missing. OGARD corroborates identifiers using event-time installation history and routes missing identity or conflicts to review.

OGARD avoids the stale telemetry acceptance but requires more review. Both methods accept the shared-source identity error. Five decisions have known synthetic physical truth; the ambiguous case has no single truth label and is not counted as a correct match.

The final column replays scripted review events separately. The evaluation measures behavior on the selected synthetic scenarios. Utility-data accuracy and human reviewer performance require separate studies.

Reproduce the release

Use Python 3.10 or later from the repository root (use python3 where appropriate). No packages, credentials or cloud services are required.

python run_validation.py --output ../ogard-rerun --verify-snapshot

The command runs the 33 automated tests, verifies both source layouts, generates decisions and comparisons, reproduces the supplied outputs, checks the website's local links and verifies the release checksums. The generated walkthrough is written to the output folder.
